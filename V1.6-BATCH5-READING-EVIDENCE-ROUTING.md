# V1.6 Batch 5 — Question-Type-Aware Reading Evidence Routing

Date: 2026-08-27

## Goal

Batch 4 intentionally left `reading-evidence` unrouted because its nine audited signals were not one homogeneous task. This batch resolves that ambiguity without adding another Repair lesson and without changing learner-state or backup schemas.

## Audit split

The canonical 388-question inventory contains nine `reading-evidence` items.

Four are Core lesson questions:

- `R02-Q1`
- `R02-Q5`
- `R04-Q3`
- `R04-Q6`

These already have direct Practice Mode Retry and therefore do not need another Core→Lab recommendation.

Five are Mini Test transfer failures and require a question-type-aware route:

| Question | Type | Route |
| --- | --- | --- |
| MR01-Q1 | True / False / Not Given | R04 → QR01 |
| MR02-Q5 | Reading Multiple Choice | R02 → QR03 |
| MR02-Q6 | True / False / Not Given | R04 → QR01 |
| MR03-Q5 | Reading Multiple Choice | R02 → QR03 |
| MR04-Q5 | Reading Multiple Choice | R02 → QR03 |

## Why this is safer than a single `reading-evidence` rule

A fixed `reading-evidence → one Lab` mapping would misdirect part of the evidence:

- TFNG evidence requires exact-claim support / contradiction / absence logic;
- MCQ evidence requires claim/evidence role recognition plus option comparison.

Batch 5 therefore keeps two explicit Improve subtypes:

- `Reading evidence · TFNG`
- `Reading evidence · MCQ`

This prevents the Improve aggregation layer from hiding one transfer route when both evidence types are active at the same time.

## Compatibility strategy

`reading-evidence-routing-v16.js` contains a small audited question-type registry for the five existing Mini Test items.

The classifier accepts either:

1. explicit `questionType` metadata when available in a future error record; or
2. the stable existing `questionId` for current saved Error Notebook items.

This means old saved errors can route immediately with no migration and no new localStorage / backup field.

Unknown `reading-evidence` question IDs remain unrouted rather than being guessed into a Lab.

## Routing rules

### TFNG evidence

`reading-evidence` + `true-false-not-given`

→ Core review `R04`

→ transfer Lab `QR01`

### MCQ evidence

`reading-evidence` + `multiple-choice`

→ Core review `R02`

→ transfer Lab `QR03`
