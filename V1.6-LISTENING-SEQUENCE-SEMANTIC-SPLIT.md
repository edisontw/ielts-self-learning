# V1.6 — Listening Sequence Semantic Split

Date: 2026-08-28
Status: implementation review; production closure pending
Baseline main: `985f4f97dc8fefc8797be9ed51dddce0c36e41fe`

## Goal

Resolve the final recurring `GAP-REVIEW` family without creating a frequency-driven LR02.

The previous semantics-first review found three questions under the historical umbrella tag `listening-sequence`:

- `ML02-Q4`
- `ML03-Q4`
- `ML04-Q3`

The three questions are not one coherent Listening skill.

## Question-level semantic split

| Question | Actual decision | New semantic tag | Teaching status |
| --- | --- | --- | --- |
| `ML02-Q4` | After passing the library, turn right immediately after the pharmacy | `listening-spatial-sequence` | QL03 already teaches continuous map/plan location tracking |
| `ML03-Q4` | After turning left at reception, locate Studio Five as the second door on the right after the kitchen | `listening-spatial-sequence` | QL03 already teaches continuous map/plan location tracking |
| `ML04-Q3` | After the morning break, Group A and Group B exchange sampling locations | `listening-procedural-sequence` | no exact existing owner; only one signal |

### Spatial route sequence — 2 signals

The two spatial questions require the learner to preserve an anchor and execute ordered directional updates. This is the same process QL03 teaches:

- fixed starting point;
- directional phrase;
- update current position;
- continue from the updated position.

However, there is still no equally exact Core lesson that forms a legitimate `Core → Lab` pair. L01 and L05 are prerequisites, not exact map-direction owners.

Decision:

`listening-spatial-sequence → TAUGHT-UNROUTED → QL03`

Because there are only two signals, no new LR Repair is justified.

### Procedural / event sequence — 1 signal

`ML04-Q3` is not map navigation. It asks what happens after a scheduled event in a field-project procedure.

Decision:

`listening-procedural-sequence → untreated but subthreshold`

One question cannot justify a new LR Repair.

## Implementation strategy — compatibility semantic retag

The original Mini Test question files retain their historical `listening-sequence` tag for backward compatibility. A dedicated semantic normalizer now resolves the precise tag using stable question IDs:

- `ML02-Q4` → `listening-spatial-sequence`
- `ML03-Q4` → `listening-spatial-sequence`
- `ML04-Q3` → `listening-procedural-sequence`

This avoids destructive migration of existing learner records while making all new evidence precise.

The normalizer is applied in three places:

1. **Mini Test runtime** — item review and newly saved Error Notebook entries use the precise semantic tag.
2. **Mini Test trends** — fresh submissions are counted with precise tags; historical `missedErrorTags` using the old umbrella tag are normalized by Mini Test form (`ML02` / `ML03` / `ML04`).
3. **Error-tag / coverage audits** — canonical counts use the semantic tag rather than the historical source label.

Unknown legacy `listening-sequence` IDs are not guessed into a subtype.

## Recurrence consequence

Before split:

- `listening-sequence` = 3 signals → recurring `GAP-REVIEW`

After split:

- `listening-spatial-sequence` = 2 signals → QL03-taught, below recurring threshold
- `listening-procedural-sequence` = 1 signal → untreated, below recurring threshold

Therefore the recurring coverage matrix is expected to become:

- V/G-REPAIR: **7 / 57**
- SKILL-REPAIR: **4 / 62**
- ROUTED-REUSE: **20 / 155**
- TAUGHT-UNROUTED: **11 / 41**
- GAP-REVIEW: **0 / 0 recurring families/questions**

The zero does **not** mean every possible Listening micro-skill now has a lesson. It means no remaining family with at least three semantically coherent Reading/Listening signals lacks an owner or safe treatment decision.

## Guardrails

- no LR02;
- no synthetic `L01/L05 → QL03` route;
- no route created from frequency alone;
- unknown legacy sequence IDs stay unsplit;
- historical Mini Test trend evidence is normalized without deleting history;
- no new localStorage key;
- no backup-schema change;

- Mini Test Test Mode and Error Notebook boundaries remain unchanged.
