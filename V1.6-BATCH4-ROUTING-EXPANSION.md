# V1.6 Batch 4 — Evidence-Aware Existing-Practice Routing Expansion

Date: 2026-08-27

## Goal

The post-Batch 3 coverage matrix scanned the canonical 388 tagged questions and showed that the next high-frequency gaps are mostly **already taught but not yet routed**. Batch 4 therefore expands existing-practice routing instead of adding another RR/LR Repair lesson.

This batch adds only mappings whose actual question semantics and existing instructional ownership are clear.

## Added routes

| Error family | Audit signals | Core review | Transfer Lab | Decision |
| --- | ---: | --- | --- | --- |
| Reading information function | 10 | R02 | QR05 | route |
| Reading contradiction | 7 | R04 | QR01 | route |
| Reading Not Given | 7 | R04 | QR01 | route |
| Reading summary logic | 7 | R02 | QR06 | route |

Total newly covered recurring evidence: **31 tagged questions**.

## Why these routes are safe

### Reading information function → R02 → QR05

The Mini Test examples ask which paragraph contains a particular function, such as:

- an information system useful to repairers and recyclers;
- trade-offs and maintenance;
- long-term operational responsibility;
- practical barriers faced by users.

`R02` teaches sentence / paragraph roles rather than word matching. `QR05` directly teaches Matching Information as `question → information-function label → locate the paragraph that performs that function`.

### Reading contradiction → R04 → QR01

These items are True / False / Not Given decisions where passage evidence directly contradicts a statement. `R04` and `QR01` already teach that **False requires contradictory evidence**, not simply absence of support.

### Reading Not Given → R04 → QR01

These items test the complementary TFNG boundary: a statement is not contradicted but is not supported by the passage. The existing R04 / QR01 instruction already owns this distinction.

### Reading summary logic → R02 → QR06

Across MR01–MR04, the tagged items are compressed completion decisions that depend on the logical role of the missing idea inside a connected summary. `R02` teaches text structure and relationships; `QR06` explicitly teaches reading a summary as one connected argument before solving its blanks.

## Deliberately deferred: Reading evidence

`reading-evidence` has 9 recurring signals, but the actual questions are heterogeneous.

Examples include:

- TFNG evidence decisions, which align with `QR01`;
- MCQ supported-statement / supporting-example decisions, which align better with `QR03`;
- general claim/evidence role recognition, which aligns with `R02`.

A single fixed Core → Lab route would therefore send some learners to the wrong transfer task. Batch 4 leaves `reading-evidence` **unrouted** until the system can make a question-type-aware transfer decision or deployed evidence supports a narrower rule.

This is an intentional negative contract and is covered by validation.

## Architecture

Batch 4 changes only the data registry in `existing-practice-routing-v16.js`.

The existing runtime remains unchanged and continues to provide:

- Improve family aggregation;
- Error Notebook `Review <Core>` / `Practise <Lab>` CTAs;
- direct lesson Retry priority;
- read-only recommendation behavior;
- V1.5 event-driven rendering.

No new:

- lesson;
- runtime layer;
- localStorage key;
- backup field;
- completion state;
- polling loop;
- MutationObserver;
- progress denominator.

## Regression requirements

`tests/validate-existing-practice-routing-v16.mjs` must verify:

- all four new family counts and destinations;
- `reading-evidence` remains unrouted;
- RR01 / RR02 / LR01 stay owned by Skill Repair;
- skill constraints prevent cross-routing;
- every route destination exists;
- routing remains read-only and event-driven.

`tests/browser-existing-practice-routing-v16.html` must verify in a real browser:

- the four new families appear on Improve with the correct route;
- the matching Error Notebook cards receive the correct Core / Lab CTAs;
- `reading-evidence` receives no fixed route;
- RR02 inference receives no duplicate reuse route;
- a normal R05 lesson error still keeps direct `Retry question` priority;
- Mini Test errors never become fake single-question Retry items, including after Learn → Improve rerender;
- R02 and QR05 route navigation render real lessons successfully.

## Contracts preserved

- 30-unit core denominator unchanged;
- VG04 / VG05 ownership unchanged;
- RR01 / RR02 / LR01 ownership unchanged;
- Test Mode remains one-submission / no single-question Retry;
- local learner-state and backup schemas unchanged;
- standard `#/lesson/<id>` navigation unchanged.
