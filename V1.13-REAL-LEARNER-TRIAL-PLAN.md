# V1.13 Real Learner Trial / Product Hardening

Status: **PLANNING / UAT START**  
Start date: **2026-08-30**

## Goal

Validate whether the existing product actually delivers its primary promise:

> the learner should know the highest-value next action without random navigation.

V1.13 is not a content-expansion milestone. The product already has sufficient Core, Repair, Labs, Mini Tests, Full Mocks, Writing and Speaking material. The remaining uncertainty is journey quality.

## Core principle

`OBSERVE FRICTION → REPRODUCE → MINIMAL FIX → REGRESSION TEST → DEPLOYED VERIFY`

Do not add a new route, Repair, lesson, Mock, Mini Test, prompt bank or account feature without a concrete learner-journey failure.

## Phase A — seeded production UAT

Run the following five journeys against production and record the exact state, action, expected result and observed result.

### A1. New learner activation

Target flow:

`LAND → QUICK PLACEMENT → RESULT → STUDY PLAN → TODAY → FIRST HIGH-VALUE ACTION`

Check:

- learner understands why Placement is useful;
- result does not imply fake IELTS precision;
- creating a Study Plan is discoverable;
- Today provides one obvious primary action;
- prerequisites do not create a dead end;
- mobile 390 px flow remains usable;
- learner can understand the difference between Learn / IELTS / Improve / Progress without reading long instructions.

### A2. Error → Repair → Retry loop

Target flow:

`WRONG → EXPLANATION → SAVE ERROR → IMPROVE / ERROR NOTEBOOK → REPAIR OR EXISTING TEACHING → RETRY → CORRECTED → REVIEW DUE`

Check both:

- a direct Practice Mode error with single-question Retry;
- a Test Mode error where fake single-question Retry must not appear.

Verify:

- the recommended Repair/review matches the actual error family;
- completed/corrected state updates immediately;
- no stale Error Notebook CTA remains after correction;
- return/context continuity is preserved.

### A3. Test transfer loop

Target flow:

`LAB / MINI TEST / FULL MOCK → SUBMIT → ITEM REVIEW → PRIORITY → TARGETED PRACTICE → RETURN TO REVIEW`

Use at least:

- one Question Type Lab;
- one Mini Test;
- MA02 Listening or Reading.

Verify:

- Test Mode boundaries remain explicit;
- priority ranking is understandable;
- targeted practice is specific enough to be useful;
- learner can return to the submitted review without losing context;
- repeated signals route to existing teaching owners instead of duplicate Repair content.

### A4. Productive skill loop

Writing target:

`PROMPT → ATTEMPT → SELF-CHECK → COPY AI REVIEW PROMPT → RETURN FEEDBACK PRIORITIES → REVISION / RETRY`

Speaking target:

`SAMPLER → TRANSCRIPT → SELF-CHECK → AI REVIEW PROMPT → RETURN FEEDBACK PRIORITIES → RETRY`

Verify:

- external-AI handoff is understandable without requiring a paid platform;
- returned feedback is treated as coaching priorities, not an official band;
- revision/retry evidence visibly changes the learner state;
- transcript-only limitations remain explicit for Speaking pronunciation/fluency signals.

### A5. Returning learner continuity

Seed a learner with:

- completed lessons;
- due review items;
- at least one unresolved error;
- one recent Mini Test / Full Mock result;
- productive evidence;
- an active Study Plan.

Target flow:

`RETURN AFTER SEVERAL DAYS → TODAY → DUE REVIEW / HIGH-VALUE ACTION → COMPLETE → NEXT ACTION`

Verify:

- due retrieval appropriately outranks low-value new material;
- completed lessons are not presented as new work;
- recent repetition penalty prevents obvious looping;
- Study Plan and Today do not contradict each other;
- Progress explains why the learner is being sent to the next action.

## Phase B — friction classification

Every finding must be classified before implementation:

- `P0 BLOCKER` — cannot continue / data loss / broken state;
- `P1 HIGH` — next action is wrong, misleading or materially difficult to find;
- `P2 MEDIUM` — understandable but unnecessarily confusing or repetitive;
- `P3 LOW` — polish only; no learning-loop impact.

Also tag the failure type:

- navigation;
- recommendation;
- state synchronization;
- explanation/copy;
- mobile/accessibility;
- performance;
- content correctness;
- Test Mode boundary;
- productive-feedback handoff;
- data portability/diagnostics.

## Phase C — implementation gate

Only P0/P1 findings automatically justify implementation.

P2 requires either repeated observation or a clearly low-risk/high-value fix.

P3 should normally be deferred until higher-impact findings are closed.

For every accepted fix:

1. add a reproducible test fixture or seed;
2. implement the smallest change;
3. add static/browser regression coverage;
4. run full `npm test` and relevant browser matrices;
5. merge through PR;
6. verify deployed production behavior before closure.

## Phase D — small real-user trial

After seeded UAT is stable, test with a small number of representative IELTS learners if available.

Suggested observation tasks:

1. start from a fresh browser and decide what to do first;
2. make a mistake and find how to improve it;
3. complete a timed IELTS activity and decide what to practise next;
4. use one Writing or Speaking AI-feedback handoff;
5. return later and decide what to do without external instructions.

Observe behavior rather than asking only whether the interface is liked.

Record:

- where the learner hesitates;
- where they choose an unintended route;
- where terminology is misunderstood;
- whether the recommended next action is trusted;
- whether the learner can explain why that action is recommended.

Do not store private learner content in the repository.

## Closure criteria

V1.13 can close when:

- all five seeded journeys pass on deployed production;
- no unresolved P0/P1 journey findings remain;
- fixes have regression coverage;
- mobile 390 px versions of the critical journeys pass;
- the learner can always identify a reasonable next action from Today / result / Improve states;
- no new content was added without evidence;
- a closure document records remaining accepted P2/P3 limitations.

## Explicit non-goals

V1.13 does not include by default:

- MA03 or more Full Mocks;
- MR05 / ML05;
- more generic Core lessons;
- more Task 2 prompts;
- more Speaking prompt volume;
- new Repairs from sparse signals;
- account/cloud sync;
- PWA/offline installation;
- official IELTS band prediction;
- automatic pronunciation scoring;
- renewed V1.6 semantic-gap mining.
