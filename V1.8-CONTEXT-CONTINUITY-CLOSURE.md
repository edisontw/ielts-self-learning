## Learner-flow behavior now closed

### Test / Mock result → targeted practice → return

A submitted Mini Test / Full Mock can route through an evidence-backed priority to an existing Core/Lab/Repair destination. The destination now exposes a named `Return to ... review` action.

Because the exact item-level result is primarily runtime state, the return path uses a bounded `sessionStorage` read-only snapshot of that submitted review. Returning never reopens submitted Test Mode as editable.

The snapshot:

- retains the result summary, priorities and full item review;
- retains authorized priority links so another targeted practice destination can be chosen;
- removes/disables submitted Test/Mock actions and form controls;
- expires after two hours;
- does not alter permanent learner-data schema.

### Error Notebook → targeted practice → return

Error Notebook / Improve routes now carry an explicit session-only return intent. A destination lesson can return to `#/improve`; when an originating error ID is available the runtime refocuses that error after return.

## Architecture guardrails

- session-only `ielts-return-context-v18` state;
- no new learner `localStorage` field;
- no browser-history dependency;
- no document-wide observer added by this feature;
- shared V1.5 render lifecycle reused;
- existing scoring, Repair ownership, Test Mode semantics, storage schema and 30-unit denominator unchanged.

## QA issue found and resolved

The first PR browser run exposed a restore-timing race: origin capture and the destination return banner worked, but the returned MA02 Reading snapshot could be overwritten/missed during hash-render/reload sequencing. The restore path was made deterministic by retrying the enhancement pass after hash/page-show rendering while keeping the same session-only/read-only model.
