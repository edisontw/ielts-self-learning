# V1.6 Evidence-Driven Reading / Listening Skill Repair

Date: 2026-08-27

## Goal

Extend the existing error → repair → retry loop to high-frequency **Reading / Listening process errors** without misclassifying them as Vocabulary / Grammar problems and without changing the first 30-unit curriculum denominator.

V1.6 begins from observed question-bank evidence, not from a wish list of topics.

## Skill-aware audit

`tests/audit-error-tags.mjs` now records both the semantic error family and the question skill. This matters because Full Mock uses some compact generic tags such as `detail`, `main-idea`, and `number`.

A generic tag alone is not enough to choose a skill Repair unit.

## Batch 1 selection

### RR01 — Main Idea vs Supporting Detail

Evidence:

- 23 Reading main-idea signals;
- accepts `reading-main-idea`;
- accepts bare Full Mock `main-idea` **only when `error.skill === reading`**.

Learning target:

- identify the paragraph-level claim / function;
- separate topic from main idea;
- reject true-but-too-narrow supporting details;
- use contrast, qualification, and conclusion language to identify direction.

Practice:

- three new paragraph contexts;
- three guided checks;
- normal wrong → Retry → correct all → Finish mastery gate.

### LR01 — Track the Final Number

Evidence:

- 27 Listening number signals;
- accepts `listening-number`;
- accepts bare Full Mock `number` **only when `error.skill === listening`**.

Learning target:

- predict whether the question needs a time, date, price, quantity, or duration;
- hold early numbers provisionally;
- notice correction / update language;
- verify the final value and unit.

Practice uses real production audio rather than text pretending to be Listening:

1. `media/audio/question-type-labs/ql02-b-pottery-workshop-booking.mp3`
   - distinguishes date, start time, arrival time, and fee;
2. `media/audio/question-type-labs/ql06-c-office-renovation-date.mp3`
   - tracks April → May → desk arrival on the 12th → final staff return on 15 May.

Both recordings were already QA-approved and production-live in the Question Type Lab audio pack. V1.6 reuses them in Practice Mode; replay and post-attempt transcript review are allowed.

## Architecture boundary

V1.6 deliberately keeps two Repair categories separate.

### Vocabulary / Grammar Repair

Existing shared registry:

- VG01–VG05
- existing placement + error-tag behavior preserved
- existing Improve section remains Vocabulary + Grammar Repair

### Reading / Listening Skill Repair

New registry:

- `skill-repair-registry-v16.js`
- RR01 / LR01
- requires observed error evidence
- uses explicit `errorSkills` constraints
- does not enter the V/G `REPAIR_LESSONS` registry
- therefore does not silently change existing V/G ranking behavior

`adaptive-data.js` adds a generic `repairMatchesError(lesson, error)` helper:

1. the tag must match `lesson.triggerTags`;
2. if `lesson.errorSkills` is declared, the question skill must also match.

Existing V/G lessons do not declare `errorSkills`, so their previous behavior is unchanged.

## Runtime

V1.6 reuses V1.5's event-driven lifecycle. It does not add polling or a MutationObserver.

`repair-route-v15.js` remains the one route renderer and now accepts:

- `VG##`
- `RR##`
- `LR##`

The renderer adds only two generic capabilities needed by skill Repair:

- optional Reading context before a guided question;
- optional production audio / transcript practice blocks.

Existing `data-lrv` contracts continue to own option selection, Check, Retry, note persistence, and the all-correct mastery gate.

`skill-repair-runtime-v16.js` adds:

- a separate Learn index;
- a separate Improve recommendation surface ranked only by matching active errors;
- a small completion bridge for RR/LR because the existing V/G interaction runtime intentionally resolves completion from the V/G registry.

State remains in the same `ielts-adaptive-v1.repairProgress` structure. No new localStorage key or backup schema is introduced.

## Regression gates

`tests/validate-skill-repair-v16.mjs` verifies:

- audit counts: RR01 = 23, LR01 = 27;
- bare `main-idea` cannot route a Listening question to RR01;
- bare `number` cannot route a non-Listening question to LR01;
- existing VG04 cross-skill paraphrase routing remains compatible;
- RR01/LR01 remain outside the V/G registry and `/30` denominator;
- LR01 production MP3 files exist and are non-trivial;
- both units contain three valid guided checks;
- Finish remains blocked until every check is correct;
- V1.6 contains no polling / MutationObserver lifecycle.

Browser smoke adds:

- Learn Skill Repair marker;
- direct `#/lesson/RR01` route;
- direct `#/lesson/LR01` route;
- a same-origin Chromium interaction harness that executes:
  - RR01 wrong → Check → Retry → correct all → Finish;
  - persistence of RR01 completion in shared adaptive state;
  - HTTP reads for both LR01 production MP3 assets.
