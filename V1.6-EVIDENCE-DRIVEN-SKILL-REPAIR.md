# V1.6 Evidence-Driven Reading / Listening Skill Repair

Date: 2026-08-27

## Goal

Extend the existing error → repair → retry loop to high-frequency **Reading / Listening process errors** without misclassifying them as Vocabulary / Grammar problems and without changing the first 30-unit curriculum denominator.

V1.6 begins from observed question-bank evidence, not from a wish list of topics.

## Skill-aware audit

`tests/audit-error-tags.mjs` records both the semantic error family and the question skill. This matters because Full Mock uses compact generic tags such as `detail`, `main-idea`, `number`, and `inference`.

A generic tag alone is not enough to choose a skill Repair unit.

| Skill family | Tagged questions | Main sources |
| --- | ---: | --- |
| Listening · number | **27** | Full Mock + Labs + Mini Tests |
| Reading · main idea | **23** | Core + Full Mock + Mini Tests |
| Reading · detail | 21 | Full Mock |
| Listening · detail | 16 | Full Mock |
| Listening · distractor | 14 | Core + Full Mock + Labs + Mini Tests |
| Listening · correction | 11 | Core + Labs + Mini Tests |
| Reading · scope | 10 | Core + Labs + Mini Tests |
| Reading · inference | 9 | Full Mock + Mini Tests |

Paraphrase and answer-type are not selected here because V1.4 already routes those transferable language-system patterns to VG04 and VG05.

## Batch 1

### RR01 — Main Idea vs Supporting Detail

Evidence:

- 23 Reading main-idea signals;
- accepts `reading-main-idea`;
- accepts bare Full Mock `main-idea` only when `error.skill === reading`.

Learning target:

- identify the paragraph-level claim / function;
- separate topic from main idea;
- reject true-but-too-narrow supporting details;
- use contrast, qualification, and conclusion language to identify direction.

### LR01 — Track the Final Number

Evidence:

- 27 Listening number signals;
- accepts `listening-number`;
- accepts bare Full Mock `number` only when `error.skill === listening`.

Learning target:

- predict whether the question needs a time, date, price, quantity, or duration;
- hold early numbers provisionally;
- notice correction / update language;
- verify the final value and unit.

Practice uses real production audio rather than text pretending to be Listening:

1. `media/audio/question-type-labs/ql02-b-pottery-workshop-booking.mp3`
2. `media/audio/question-type-labs/ql06-c-office-renovation-date.mp3`

Both recordings were already QA-approved and production-live in the Question Type Lab audio pack.

### RR02 — Infer Only What the Evidence Supports

Evidence:

- 9 Reading inference signals across Mini Test + Full Mock;
- accepts `reading-inference`;
- accepts bare Full Mock `inference` only when `error.skill === reading`;
- rejects a Listening `inference` error through the existing skill constraint.

Learning target:

1. identify the explicit evidence;
2. state the smallest conclusion that reasonably follows;
3. reject answers that add a new cause, stronger certainty, larger quantity, wider population, or universal claim;
4. distinguish a supported inference from outside knowledge or speculation.

Practice:

- three new evidence contexts;
- explicit overclaim distractors;
- normal wrong → Retry → correct all → Finish mastery gate.

No runtime layer was added for RR02. The existing V1.6 Skill Repair registry, Learn/Improve surfaces, unified Repair route renderer, completion bridge, and adaptive state all handle it data-first.

## Architecture boundary

### Vocabulary / Grammar Repair

Existing shared registry:

- VG01–VG05
- existing placement + error-tag behavior preserved
- existing Improve section remains Vocabulary + Grammar Repair

### Reading / Listening Skill Repair

`skill-repair-registry-v16.js` currently contains:

- RR01 — Main Idea vs Supporting Detail
- RR02 — Infer Only What the Evidence Supports
- LR01 — Track the Final Number

Skill Repair:

- requires observed error evidence;
- uses explicit `errorSkills` constraints;
- stays outside V/G `REPAIR_LESSONS`;
- does not change the core `/30` denominator.

`adaptive-data.js` provides `repairMatchesError(lesson, error)`:

1. the tag must match `lesson.triggerTags`;
2. if `lesson.errorSkills` is declared, the saved question skill must also match.

Existing V/G lessons do not declare `errorSkills`, so their previous behavior is unchanged.

## Runtime

V1.6 reuses V1.5's event-driven lifecycle. It does not add polling or a MutationObserver.

`repair-route-v15.js` remains the one route renderer and accepts:

- `VG##`
- `RR##`
- `LR##`

The renderer supports optional Reading context blocks and optional Listening production audio / transcript blocks.

Existing `data-lrv` contracts continue to own option selection, Check, Retry, note persistence, and the all-correct mastery gate.

`skill-repair-runtime-v16.js` owns:

- the separate Learn index;
- the separate Improve recommendation surface ranked by matching active errors;
- the RR/LR completion bridge.

State remains in `ielts-adaptive-v1.repairProgress`. No new localStorage key or backup schema is introduced.

- Reading detail → R02 / R05 / QR02 / QR03
