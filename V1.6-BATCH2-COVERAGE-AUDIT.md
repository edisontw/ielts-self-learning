# V1.6 Batch 2 — Reading / Listening Repair Coverage Audit

Date: 2026-08-27

## Purpose

Before adding another Reading / Listening Skill Repair unit, compare the remaining high-frequency error evidence with what the existing Core lessons and Question Type Labs already teach.

The decision rule is:

`REPEATED ERROR EVIDENCE + WEAK INSTRUCTIONAL COVERAGE → NEW REPAIR`

If a skill is already taught explicitly, prefer better routing / reuse rather than duplicating another short lesson.

## Why the five larger families do not need another Repair lesson

### Reading detail — reuse R02 / R05 / QR02 / QR03

The generic Full Mock `detail` family is broad rather than one missing decision rule.

Existing instruction already covers its main failure modes:

- R02 distinguishes claim, evidence, example, contrast, and conclusion;
- R05 explicitly teaches the **detail trap** in Matching Headings;
- QR02 rejects headings that describe only one example or sentence;
- QR03 explicitly teaches the **true detail, wrong answer** MCQ trap.

Adding a generic “find details” Repair would be less precise than routing the learner to the lesson matching the actual detail error subtype.

### Listening detail — reuse L02 / L03 / L05 / QL05

Existing instruction covers several distinct reasons a detail can be missed:

- L02: connected speech and chunked detail retrieval;
- L03: paraphrased spoken detail;
- L05: question preview and answer-type prediction;
- QL05: exact requested-detail retrieval and concise answer form.

A generic Listening-detail Repair would collapse different causes into one lesson and reduce diagnostic value.

### Listening distractor — reuse L04 / QL01

This is already one of the strongest-covered listening decisions in the site.

L04 explicitly teaches:

`old plan → correction / rejection → final meaning`

and trains markers such as `but`, `actually`, `instead`, `changed my mind`, and `in the end`.

QL01 repeats the same decision under question-type pressure and tracks options as possible / rejected / final.

Therefore the next improvement should be routing rather than duplicated content.

### Listening correction — reuse L04 / QL06

L04 already treats corrections and changed decisions as a core distractor pattern. QL06 reinforces final spoken detail after grammar prediction and correction language.

The repeated correction errors indicate a transfer problem, not an absence of teaching.

### Reading scope — reuse R04 / QR01 / QR03

R04 explicitly teaches scope words and claim strength:

- `some → all`
- `can → will`
- `one reason → main reason`

QR01 applies exact-claim comparison under TFNG timing. QR03 applies scope control to Reading MCQ distractors.

This is already direct, repeated instruction; another scope lesson would duplicate it.

## The untreated gap: Reading inference

Reading inference appears **9 times** across Mini Tests and Full Mock evidence, including questions such as:

- concluding that flagship-only shade may fail to reach people facing the greatest heat risk;
- inferring that a system can lose function even while it still looks healthy;
- inferring that formal openness does not guarantee practical accessibility;
- inferring why a particular building or strategy may benefit more from stated conditions.

These questions require a controlled step beyond direct retrieval:

`explicit evidence → limited supported conclusion`

The current curriculum tests this skill but no Core lesson or Question Type Lab directly owns `reading-inference` as an instructional/error target. R02 and R04 provide useful supporting habits, but neither gives a focused inference decision rule or retry loop.

This is therefore the only Batch 2 family that currently justifies a new Skill Repair unit.

## Batch 2 implementation decision

Add:

### RR02 — Infer Only What the Evidence Supports

Target behavior:

1. identify the explicit evidence;
2. state the smallest conclusion that must or reasonably can follow;
3. reject options that add a new cause, certainty, quantity, comparison, or universal claim;
4. distinguish a supported inference from outside knowledge or speculation.

Routing:

- `reading-inference`
- generic Full Mock `inference` only when `error.skill === reading`

Architecture:

- add RR02 to the existing V1.6 Skill Repair registry;
- reuse the existing shared Repair route renderer and lifecycle;
- reuse the same `ielts-adaptive-v1.repairProgress` state;
- no new localStorage key;
- no backup schema change;
- no change to the 30-unit core denominator;
- no MutationObserver / polling layer.

## Future routing work

The audit also identifies a later non-content improvement: high-frequency families already covered by Core/Labs should eventually route the learner more specifically to those existing units rather than merely increasing pressure to create more Repair extensions.

That routing work should preserve the distinction between:

- **instruction gap** → Skill Repair;
- **transfer failure** → existing Core/Lab revisit + unseen retry;
- **language-system gap** → Vocabulary / Grammar Repair.
