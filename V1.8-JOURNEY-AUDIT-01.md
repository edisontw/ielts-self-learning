# V1.8 Journey Audit 01 — Baseline Friction Review

**Date:** 2026-08-30  
**Baseline:** main `36d311b3f9fcbea988ee41e59e042385f66c4af5`  
**Scope:** learner-flow audit only; no new curriculum/Test/Repair content.

## Executive finding

The current system is functionally mature. The largest remaining friction is not missing teaching content; it is **continuity after evidence is generated**.

Two learner journeys should be optimized first:

1. **Mini Test / Full Mock result → small number of priorities → one next action**.
2. **Error / Repair / existing practice → explicit return to the activity that produced the evidence**.

## Decision

### V1.8 implementation order

1. **Result prioritization** for Mini Tests + Full Mocks.
2. **Origin / return context continuity** across targeted practice and Repair.
3. Today ranking consolidation.
4. Productive-skill explicit revision CTA.
5. Wider mobile/accessibility/performance pass.

## Result-prioritization guardrails

The result page may summarize only destinations already authorized by current learning logic:

- existing-practice routes from V1.6/V1.7;
- dedicated audited Skill Repair (`RR01–RR03`, `LR01`);
- existing V/G Repair where its trigger taxonomy already applies.

It must **not**:

- create a new Repair lesson;
- create a new route from one test form;
- aggregate Listening and Reading merely because tags share the same word;
- turn a Mini Test/Full Mock item into fake single-question Practice retry;
- replace the full item review;
- produce an official or falsely precise IELTS score.

Priority grouping must be skill-aware and destination-aware. The full item review remains below the summary.

## Acceptance target for first implementation

After a Mini Test or Full Mock submission with multiple errors, the learner sees:

1. attempt summary;
2. **Your priorities** — up to 3 coherent, authorized families;
3. **Recommended next step** — one existing Repair/Core/Lab destination;
4. complete item-by-item review below;
5. existing Save errors / retake / Back behavior preserved.

If no missed item maps to an already-authorized destination, the result page must say to review the missed items below rather than inventing a recommendation.
